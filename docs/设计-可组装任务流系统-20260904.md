# 设计——圆桌派可组装任务流系统（A→B→C 一次成型——2026-09-04）

> 仓：zerg-cocoon/圆桌派（zerg-roundtable）——状态：**设计稿待Mr2109确认**
> 定位（Mr2109）：圆桌派 = **AI 群策群力引擎**——13 Block 流水线只是第一个任务流——未来各种讨论产出任务/项目各自组装任务流——参照 Dify（图引擎 graphon/14+ 节点类型）/n8n（INodeType 自描述节点/四类节点/执行引擎解耦）——调研结论见附录一
> 差异化判断：Dify/n8n 只有单发 LLM 节点——圆桌派「讨论」是复合节点（主持人+多角色+投票+门禁+多轮状态机）——**讨论块必须是一等节点**

---

## 一、现状盘点（哪些已对、哪些要改）

**已对（引擎底盘通用——不动）**：
- 引擎只懂「讨论推进」，Block 内容由模板给（run.rs:80 `for blk in tmpl.blocks`——引擎不知道小说）
- 断点续跑按 `current_block` 索引推进——与 Block 内容无关
- 门禁 quality_check 数值判定与议题无关
- 模板注册点已留：`get_template(project_type)` match 分发（novel.rs:205）

**要改（三处硬编码）**：
1. `ProjectTemplate` 的字段全是 `&'static`——模板只能编译期写死在 Rust 里，无法运行时装载
2. 新建会话表单写死小说类型/字数（NOVEL_TYPES/LENGTHS 常量）——多模板后应从模板声明读
3. 上下文组装隐式（讨论流全文投喂）——多模板任务节点产物需要显式变量池

## 三、A 案：模板声明文件化（地基——1 期）

### 3.1 模板声明格式（`templates/*.flow.json`）

```jsonc
{
  "id": "novel",                        // project_type——会话表引用
  "name": "小说设定流水线",
  "version": 1,
  "description": "13 Block 群策产出小说世界观与正文设定",
  "inputs": [                           // 会话创建时要用户填的
    {"key": "topic", "label": "主题", "required": true},
    {"key": "length", "label": "篇幅", "options": ["短篇","中篇","长篇","超长篇"], "default": "长篇"}
  ],
  "roles": {                            // 角色团（5 作者+主持人——可自定义）
    "moderator": {"name": "主持人", "role": "整合/引导"},
    "panel": [
      {"name": "司世", "zi": "字观止", "specialty": "世界观", "description": "……"},
      // …5 作者
    ]
  },
  "nodes": [                            // A 案=线性序列；B 案升级为带分支的图
    {"id": "n0", "kind": "discussion",
     "name": "类型",
     "desc": "（BLOCK_DESC 逐字搬入）",
     "fields": ["类型", "篇幅"],
     "fm": "## 类型:{}\n## 篇幅:{}"},
    {"id": "n1", "kind": "discussion", "name": "故事核", "desc": "…", "fields": ["故事核"], "fm": "## 故事核:{}"},
    // …13 个
  ],
  "gate": {                             // 门禁默认规则（节点可覆盖）
    "pass_score": 80, "max_cycle": 3
  }
}
```

### 3.2 运行时装载（替换 `&'static`）

```rust
pub struct ProjectTemplate {
    pub id: String,                     // 去 'static
    pub blocks: Vec<Block>,             // Vec 拥有
    pub authors: Vec<Author>,
    pub moderator: Moderator,
    pub inputs: Vec<TemplateInput>,
    pub gate: GateRule,
}
pub fn load_template(id: &str) -> Result<ProjectTemplate, RtError>  // 读 templates/ 目录 JSON——内置 novel 回退编译期版
```

- **向后兼容**：`novel.flow.json` 声明文件 + 编译期 NOVEL_BLOCKS 双轨——启动时若目录无声明文件用内置，有则文件优先（可热改文案不重编译）
- **对齐验证**：novel.flow.json 装载结果与 NOVEL_BLOCKS 逐字段断言相等（测试保护——内容资产不动）

### 3.3 变量池（显式上下文总线）

- DB 加 `flow_vars` 表：`(sid, key, value, from_node, ts)`——每个节点锁定时写入产物（键=字段名，值=锁定值）
- 上下文组装改为：讨论流历史 + `flow_vars 检索`（当前块 desc 引用 `{{变量}}` 占位符自动替换）+ 向量记忆（保留）
- 例：「故事核」锁定后写入 `flow_vars[故事核]`——Block 3 的 desc 里写 `围绕{{故事核}}展开读者定位讨论`——装载时替换
- 现有「讨论流全文投喂」保留为兜底——变量池是精确引用层

## 四、B 案：四类节点 + 受控 DAG（2 期）

### 4.1 节点类型（对齐 n8n 四类 + 招牌复合节点）

| kind | 职责 | 执行语义 |
|---|---|---|
| `discussion` | **招牌复合节点**——主持人+panel 多角色多轮+投票+门禁 | 现有 process_block 状态机原样 |
| `single` | 单问 LLM——一次调用拿结果（摘要/翻译/抽取/命名） | prompt 模板 + 变量替换 → 写 flow_vars |
| `tool` | 工具调用——HTTP/本地脚本/知识库检索（复用虫族工具层） | 参数模板 → 执行 → 输出写 flow_vars |
| `gate` | 门禁/分支——数值评分/条件判断/人工确认挂起 | 规则判定 → 决定走哪个后继节点 |

### 4.2 受控 DAG（不做全自由图）

- 节点声明 `next: ["n2"]` / 条件分支 `next_by: {"gate_pass": "n2", "gate_fail": "n1b"}`——**边在节点上，不搞独立连线对象**（声明文件简单可手写——可视化是 C 案的事）
- 执行引擎：拓扑序推进 + gate 分支选择 + 断点续跑改为记录 `current_node`（向后兼容 current_block——novel 模板 node id = block index 映射）
- 循环：`gate` 节点 `back_to` 声明回跳（如评审不过回上一讨论块——限 3 次防死循环）

### 4.3 单问/工具节点的模型选择

- 节点级 `model` 声明（缺省用会话 provider）——单问/工具可用便宜快模型，讨论块用重模型——**模型分级省钱**（对齐虫族「模型是可替换算子」）

## 五、C 案：可视化编排（3 期）

- egui 画布：节点框 + 连线（左进右出）——拖拽排布，属性面板编辑节点参数
- 本质是**模板声明文件的图形编辑器**——读写同一 JSON——C 做完 A 的手写声明仍在（文本 grep-able 是刚需）
- 分期起步：先只读视图（导入声明文件画出图）→ 再编辑（拖拽/连线/保存）→ 最后模板库管理（列表/复制/分享）
- 布局算法：层级拓扑排布（B 案 DAG 天然分层）——手拖位置存 `layout` 字段可选

## 七、风险与回滚

- **最大风险**：B2 主循环改造（线性→DAG）波及断点续跑——对策：novel 模板 `next` 隐式线性（不声明=顺序），改造后 novel 行为等价——专测「改造前后 novel 全流程 mock 输出一致」
- **变量池膨胀**：flow_vars 只存锁定产物（每块几条），量可控；上线后观测再定清理策略
- **{{变量}} 未定义**：装载期校验引用存在性，未定义→启动 ERROR（errors 表）不静默
- **回滚**：A 案纯增量（内置回退在）；B 案每步 mock 测试可 revert；C 案独立 UI 模块可整块卸载
