## 〇、源码调研结论（v2 新增——可借鉴/不借鉴逐项判定）

### 0.1 三家架构一句话

- **graphon**（Dify 图引擎本体）：`Graph`（节点+边+拓扑）→ `GraphEngine`（事件驱动执行循环 Generator[GraphEngineEvent]）→ `VariablePool`（二级字典 selector=(node_id, name)）→ `Node[T]` 基类（`_run()` 抽象 + NodeData pydantic 自校验 + version + retry/error_strategy 声明）
- **Dify 应用层**：node_factory 注册表（NodeType→class 映射，lazy 加载）+ human_input 人在环（form 提交→PauseReason→暂停/恢复）+ DSL importer（YAML→Graph plan，装载期校验 unsupported 节点）
- **n8n**：INodeType 自描述（description+execute）+ 执行引擎（nodeExecutionStack 栈推进 + **waitingExecution 多输入汇聚等待** + 断点恢复）+ **AI Workflow Builder**（Planner/Supervisor/Builder 多代理 + validate-loop 生成-校验-修复循环）

### 0.3 明确不借鉴（过度工程判定）

| 不借鉴 | 理由 |
|---|---|
| Dify 11 容器部署栈（Redis/Weaviate/Celery…） | 单人本地单机——rusqlite+进程内线程足够（已如此） |
| n8n 500+ 集成节点生态 | 圆桌派 tool 节点按需加，不做集成平台 |
| 多租户/workspace/权限/协作编辑 | 单人系统 |
| n8n Queue 模式（Bull/Redis 分布式执行） | 单机串行引擎——本机就够，远期集群靠虫族 fleet |
| graphon 事件流 Generator 全家桶（20+ 事件类型） | 圆桌派引擎同步推进+落库——不需要事件总线，日志系统已覆盖观测 |
| 版本化节点多版本共存（IVersionedNodeType） | 单机自控——版本变了改声明即可，无需运行时多版本 |

### 0.4 关键差异确认（Mr2109核心关切）

**「他们是人搭流程，圆桌派是 AI 搭模块」的落地态**：

| 层 | 人（手动） | AI（自主） | 共用机制 |
|---|---|---|---|
| 模板声明 flow.json | 手写 JSON（grep-able） | validate-loop 生成 | **同一 schema 同一装载器**——人写的和 AI 生成的走完全相同的校验与执行路径，无特权通道 |
| 流程规划 | 直接写/改 JSON | **圆桌讨论出方案**（Plan Mode） | 讨论产出=结构化 plan（节点清单+连接+理由）→ 人确认 → 转 JSON |
| 节点参数 | UI 表单/JSON 编辑 | 讨论块由模型自决（投票/确认） | 节点级 `human_gate` 开关：AI 全自动跑 / 每步人确认 / 仅关键点确认——三档由模板声明 |
| 运行干预 | 停止/暂停按钮 | 引擎自动重试（RtError 分类） | 日志对话框同看（AI 与人的操作都进 errors/日志） |

即：**AI 与人在同一份 flow.json、同一个装载器、同一个执行引擎上会合**——不是两套系统。

## 一、总体架构（v2 修订——三层+AI 建流回路）

```
┌────────────────────────────────────────────────────────┐
│ C·编排层   人：egui 画布（读/画/存 flow.json）           │
│            AI：建流回路（讨论规划→JSON生成→validate-loop）│
│            共用：同一 flow.json schema + 装载器          │
├────────────────────────────────────────────────────────┤
│ B·节点层   trait RtFlowNode（kind/version/execute）      │
│            discussion(招牌复合) / single / tool / gate   │
│            human_gate 三档（全自动/关键点/每步）          │
├────────────────────────────────────────────────────────┤
│ A·模板层   flow.json（serde 校验）→ 装载器(builder+校验) │
│            → ProjectTemplate（去 static——运行时装载）    │
├────────────────────────────────────────────────────────┤
│ 底盘（不动）讨论状态机/门禁/断点续跑/RtError/日志系统      │
│ 变量池（v2 升级）flow_vars 表 (sid, node_id, key, value) │
│   selector=(node_id,key)——{{n1.故事核}} 引用替换        │
│   前缀保留：sys./env./conv.                              │
└────────────────────────────────────────────────────────┘
AI 建流回路（新增）：
  用户需求 → [圆桌讨论=Planner] → 人话方案+Mermaid 图 → 人确认
         → JSON 生成（Builder）→ 装载器校验 ─┬→ 过：入库可跑
              ↑______________失败(错误清单)___┘ ≤N 次
```

## 二、A 案（模板声明文件化——内容对齐 v1，按 v2 升级）

- flow.json schema **不变**（v1 第三节）——变量引用语法升级 `{{节点id.字段}}`
- 装载器升级：serde 解析 → **schema 校验 → 变量引用校验 → 图校验**（环/悬空引用）——错误清单一次性返回（对齐 graphon importer `_unsupported_node_reasons` 风格）
- ProjectTemplate 去 static 化 + novel.flow.json 双轨对齐测试（同 v1）
- flow_vars 表结构升级：`(sid, node_id, key, value, ts)`——写入点=节点锁定时；讨论流全文投喂保留为兜底
- 节点声明加 `human_gate: none|key_points|every_step`（默认 none——现有全自动不变）

## 三、B 案（四类节点——补充 v2 增量）

- trait `RtFlowNode`（借鉴 graphon Node 基类）：
  ```rust
  trait RtFlowNode {
      fn kind(&self) -> &'static str;                 // discussion/single/tool/gate
      fn version(&self) -> u32;
      fn execute(&mut self, ctx: &mut FlowCtx) -> Result<NodeOutcome, RtError>;  // FlowCtx=变量池+会话上下文+db
      // 错误策略声明（对接 RtError：Env retryable 自动重试次数/退避）——默认继承，节点可覆写
      fn retry_policy(&self) -> RetryPolicy { RetryPolicy::default() }
  }
  ```
- 四类节点（同 v1 4.1 表）+ `gate` 节点 `human_confirm` 模式（借鉴 Dify HITL：执行到此暂停→状态置 awaiting_human→UI 确认卡→批准/驳回/改字段→恢复。驳回可 `back_to` 回跳指定节点）
- 受控 DAG（同 v1 4.2）+ 汇合预留：若未来有多输入节点，按 n8n waitingExecution 模式（记录每路已到数据，最后一路到达触发）——本期不做，设计留痕
- 模型分级（同 v1 4.3）

## 四、C 案（画布 + AI 建流——v2 重心调整）

C 不只是人的画布——**AI 建流回路是 C 的一半**（Mr2109核心关切的落地）：

### C-1 只读画布（人看）
- egui 画布渲染 flow.json（节点框/连线/human_gate 标记）——拓扑分层布局

### C-2 AI 建流回路（AI 建）——借鉴 n8n Builder，圆桌派化
1. **规划=圆桌讨论**（招牌复用）：用户需求进讨论引擎，角色团围绕「流程该怎么走」讨论产出结构化方案（节点清单/每节点职责/连接/门禁点）——讨论本身就是流程质量的第一道群策把关
2. **确认卡**：方案以 Mermaid 图+人话步骤展示（借 n8n Mermaid 中间表示——省 token 且人可读）——人改/确认
3. **生成+validate-loop**：确认后生成 flow.json → 装载器全量校验 → 错误清单回喂模型修复 → 循环至通过或达上限（MAX_VALIDATE_ATTEMPTS=5）——**人与 AI 走同一装载器，无特权通道**
4. 入库 templates/ 目录立即可跑

### C-3 编辑+模板库（人改/共用）
- 画布拖拽/连线/属性面板编辑→写回同一 flow.json
- 模板库：列表/复制/删除/导入导出——AI 生成与人手写的混存同列

## 六、风险与回滚（v2 增量）

- **AI 生成质量**：validate-loop 是硬闸（schema+引用+图三重校验）——AI 最多 N 次修复，过不了就给人看错误清单人接管——永不静默入库坏流
- **AI 建流成本**：规划是一次圆桌讨论（数轮 LLM）+ 生成修复循环——本地模型零现金成本，时间可控（讨论引擎已实测速率）
- 其余同 v1 第七节（主循环改造等价性专测/变量池膨胀/回滚策略）
